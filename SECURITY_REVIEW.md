# Проверка безопасности AutoCare

Дата: 21 сентября 2026 года. Это обзор исходного кода и изолированные проверки
портфолио-MVP, а не сертификация или утверждение об отсутствии уязвимостей.

## Область проверки

Проверены Telegram-обработчики, сервисы владения ресурсами, ORM и миграции,
Gemini/RAG, API, HTML-формы, шаблоны, сессии, конфигурация, логи, зависимости
и Git-видимые файлы. Проверка секретов охватила 105 исходных Git-видимых файлов,
13 достижимых коммитов, 181 уникальный исторический blob и сообщения коммитов.
Поиск значений выполнялся без вывода самих значений.

Локальный `.env` не читался и не изменялся. Удалённые ветки не загружались;
недостижимые объекты, внешние журналы, GitHub Actions и настройки Supabase
не проверялись. Существовавшее до аудита изменение README сохранено.

## Секреты и конфигурация

Реальных секретов в проверенных текущих файлах и достижимой истории не обнаружено.
Совпадения относятся к `.env.example`, явным offline-фикстурам и обращениям к
переменным окружения. Исторически отслеживаемых `.env`, ключей, логов или копий БД
не найдено. `.env` исключён Git; шаблон содержит только заполнители.

По результатам этой проверки нет оснований требовать ротацию конкретного ключа.
Проверка по сигнатурам не доказывает отсутствия неизвестного формата секрета.
Если реальный ключ обнаружится позднее, его следует отозвать/заменить: удаление из
текущего файла не удаляет его из истории. Переписывание истории — отдельная операция.

Обязательные настройки проверяются при использовании. Примерные ADMIN_API_KEY и
WEB_SESSION_SECRET не включают доступ; секрет подписи проверяется на длину.
WEB_COOKIE_SECURE по умолчанию false для localhost HTTP. Для HTTPS его необходимо
явно включить. Силу реальных локальных ключей и параметры TLS в DATABASE_URL аудит
не проверял, поскольку `.env` не читался.

## Оценка границ доступа

- **API и сессии:** все текущие `/api/admin` операции имеют общую header-only
  зависимость авторизации; query-параметр не является ключом. Сравнение constant-time.
  CRM использует отдельную подписанную случайную сессию, HttpOnly/SameSite cookie,
  ротацию идентификатора после входа и отзыв после выхода. Ключ в cookie не хранится.
  Отсутствующие ключи/секреты закрывают доступ; OpenAPI не содержит их значений.
- **CSRF/XSS:** вход, выход и изменение статуса проверяют токен сессии. GET не
  меняет бизнес-данные. HTML autoescape включён, небезопасного вывода пользовательских
  сообщений/резюме через `safe`, Markup или innerHTML не найдено. Политика CSP и
  запрет встраивания дополняют экранирование.
- **SQL:** бизнес-запросы используют выражения SQLAlchemy и параметры. Raw SQL в
  миграциях/ingestion статический; ввод пользователя не подставляется в идентификаторы.
  Русский FTS параметризован, возвращает только активные записи, максимум 4 фрагмента.
- **IDOR:** автомобиль проверяется по Telegram ID, диалог — по владельцу перед
  чтением/записью и handoff. Callback-данные дополнительно сверяются с FSM; при
  сохранении записи повторно проверяются владелец автомобиля и активность услуги.
  Username не используется как идентификатор владельца. Admin-сервисы предполагают
  проверку оператора на границе HTTP, что выполняют существующие маршруты.
- **Логи и ошибки:** прикладные сообщения не содержат исходных исключений, промптов,
  историй и ключей. SQL echo выключен, параметры скрыты. HTTP имеет безопасную границу
  ошибок. Команда запуска Uvicorn использует `--no-access-log`; внешние прокси/другие
  конфигурации логирования находятся вне этой проверки.
- **AI/RAG:** у модели нет инструментов изменения БД, статусов или прав. Знания и
  история передаются как данные, резюме проверяется отдельной схемой, сбой Gemini
  не отключает проверки владельца. Промпты не гарантируют защиты от prompt injection:
  неверный или нежелательный текст всё ещё возможен. Документы нужно рецензировать.

## Зависимости

Прямые зависимости закреплены версиями в requirements.txt, ссылок на произвольные
Git-репозитории или сторонние индексы в нём нет. Все 54 установленных пакета были
проверены по публичному PyPI JSON API; один сетевой сбой повторно проверен успешно.
Найдена указанная выше уязвимость pip; для остальных установленных версий API
не вернул неотозванных advisory. pip-audit не был установлен; крупные инструменты
аудита и дополнительные зависимости не добавлялись.

Это проверка известных advisory на дату аудита, не проверка исходников всех пакетов,
не сканирование ОС и не гарантия отсутствия уязвимостей. Транзитивные зависимости не
зафиксированы отдельным lock-файлом; новое окружение может иметь другой набор версий.

## Проверки

Добавлено 10 регрессионных тестов: изоляция CSRF между сессиями, вытеснение анонимных
сессий, отказ при заполнении хранилища операторами, запрет чтения ссылок, выбор только
Markdown, безопасные логи aiogram, ограничения больших и chunked HTTP-тел, сохранение
малого тела и no-store для приватных ответов. Проверка ссылки переносима на Windows:
флаг symlink подменяется, а чтение запрещается mock-объектом.

```text
python -m unittest discover -s tests -v
Ran 227 tests in 14.533s — OK

python -m compileall -q app scripts tests main.py
exit code 0

python -m pip check
No broken requirements found.

git diff --check
exit code 0
```

Существующие API/CRM, ownership, статусы, Gemini fallback и RAG-тесты прошли.
Интеграционные проверки использовали одноразовый локальный PostgreSQL, не Supabase.
Сохраняется предупреждение Starlette о deprecated httpx-адаптере TestClient.

## Остаточные ограничения и действия перед публикацией

1. Обновить pip в виртуальном окружении через доверенный индекс:
   `python -m pip install --upgrade "pip>=26.2"`, затем повторить `python -m pip check`.
2. Проверить сильные независимые ключи, diff/staged-файлы и отсутствие персональных
   данных в документах/скриншотах. Не публиковать реальные логи или `.env`.
3. Перед сетевым развёртыванием настроить HTTPS, Secure cookie, TLS подключения к БД,
   минимальные права роли БД, доверенные host/proxy-настройки и сетевые ограничения.
4. Rate limiting входа, Admin API и платных AI-вызовов отсутствует. Размер тела
   ограничен, но это не защита от частых запросов, медленных соединений и расхода
   квоты. Для публичного развёртывания нужны ограничения на сетевой границе.
5. Общий admin-ключ, отсутствие персональных ролей/аудита действий, сессии одного
   процесса и отсутствие политики удаления переписок остаются ограничениями MVP.
   История сохраняется в БД, а часть диалога передаётся внешнему AI-провайдеру.
6. При развёртывании проверить собственные журналы сервера/прокси и доступ к `/docs`.
   Не включать debug/SQL echo или подробные SDK-логи с реальными данными.

Миграции, ingestion, реальный бот и Gemini не запускались. Supabase не подключался.
Сетевые обращения аудита ограничены публичными сведениями о зависимостях.
Секреты не ротировались; история Git не переписывалась; commit/push не выполнялись.
